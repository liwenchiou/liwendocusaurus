# 02. 內部需求評估單 (Internal Assessment)

> **🎯 使用時機：** PM 帶回訪談單後，與內部工程師/設計師開會討論時填寫。
> **重點原則：** 盤點技術資源，評估開發成本，殺死不切實際的幻想，收斂出真正的 MVP 範圍。

## 一、願望清單技術評估 (Feasibility & Cost)
> 💡 針對《訪談單》中的「願望」，由技術團隊給出殘酷且務實的評估。

| 客戶想要的功能 | 工程師評估 (技術可行性 / 開發成本 / 潛在風險) | 內部決議 (MVP / 放棄 / 延後) |
| :--- | :--- | :--- |
| 想要有 AI 聊天機器人 | 成本極高。需要串接 OpenAI API，且有不可控的客訴風險，超出現有預算。 | ❌ **建議移至未來擴充清單** |
| 會員 Google 登入 | 成本低。使用 Firebase Auth 可快速實作，風險低。 | ✅ **納入第一期開發 (MVP)** |
| 匯出精美的 PDF 報表 | PDF 排版極耗時。建議第一期先做 Excel (.csv) 匯出。 | ⚠️ **降級納入 (改做 Excel 匯出)** |

## 二、潛在技術風險與地雷 (Risk Management)
- **技術地雷 1**：[例如：客戶要求串接的那套老舊 ERP 系統可能沒有 API，這會導致整個專案卡死。我們必須先拿到 API 文件才能確認。]
- **依賴資源**：[例如：我們需要客戶先去申請好綠界帳號，否則金流完全無法進入測試。]
