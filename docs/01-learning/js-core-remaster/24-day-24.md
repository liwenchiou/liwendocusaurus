## 💡 【導師講義：底層真相探究】

### 1. 復活甲三部曲：Try, Catch, Finally

這是一套完整的生命週期，缺一不可：

- **`try { ... }`**：**「勇敢嘗試」**。把最可能爆炸、最危險的動作（如 Fetch 請求、JSON 解析）放進來。
- **`catch (error) { ... }`**：**「落地緩衝」**。如果上面的代碼炸了，這裡會立刻接住它。你可以在這顯示「網路不穩，請稍後再試」或記錄錯誤日誌。
- **`finally { ... }`**：**「戰後清理」**。這是最容易被忽略但最重要的。**無論成功還是失敗，這裡的代碼「保證執行」**。

### 2. 實戰必殺技：Finally 的真正用途

想像你在抓資料前，畫面上顯示了一個「轉圈圈 (Loading)」動畫：

- 如果請求成功，你要關閉轉圈圈並呈現資料。
- 如果請求失敗，你也要關閉轉圈圈（不然使用者會在那裡看到畫面卡住等一輩子）。

**這就是 `finally` 的舞台！** 將狀態復原或關閉 Loading 放進 `finally` 區塊，能避免在 `try` 與 `catch` 兩處重複撰寫清理代碼。

### 3. 主動預警：`throw new Error()`

有時候伺服器回應了 HTTP 狀態碼但非預期，或是回傳的資料「不合業務邏輯」（例如：血量是負數）。這時你可以主動引爆炸彈，拋出例外並跳到 `catch` 去處理：

```javascript title="throw-error.js"
if (data.hp < 0) {
  throw new Error("勇者數值異常，包裹有毒！");
}
```

## ⚔️ 【戰術對抗：學長與學弟的代碼對決】

### 招式示範：完整的 Fetch 錯誤處理

#### ❌ 冒險學弟：僥倖派 (只顧成功)

- **負能量評級**：🔴 斷網直接噴紅字 / 🔴 loading 轉圈圈轉到死

```javascript title="naive-fetch.js"
async function getSupplies() {
  showLoading(true);
  const res = await fetch("https://api.guild.com/items"); // 如果這裡斷網，程式碼就卡死了
  const data = await res.json();
  showLoading(false);
}
```

#### ✅ 勇者學長：穩健派 (全方位防禦)

- **利潤評級**：🟢 極致的用戶體驗 / 🟢 面試官最愛的代碼範本

```javascript title="safe-fetch.js"
async function getSupplies() {
  try {
    showLoading(true);
    const res = await fetch("https://api.guild.com/items");
    if (!res.ok) throw new Error("領取失敗！");

    const data = await res.json();
    console.log("物資：", data);
  } catch (err) {
    showErrorMessage("📢 公會警報：" + err.message);
  } finally {
    // 關鍵！無論成功失敗，都要關閉轉圈圈
    showLoading(false);
  }
}
```

## 🛖 【營火叮嚀：導師的經驗談】

:::note[🛖 營火叮嚀：導師的經驗談]

孩子，導師教你一個「職人小技巧」。

在 `catch` 裡面，不要只是單純的 `console.log(error)`。試著寫下有層次的訊息，例如：「[Auth Service] 失敗：無效的金鑰」。當半年後的你回頭修 Bug 時，你會感謝現在這個考慮周全的自己。

**「錯誤處理不是為了隱藏問題，而是為了在問題發生時，我們依然能對系統保有控制權。」**

:::

## 📝 【夥伴筆記：今日修煉精華】

> *這份筆記是你的隨身護身符，卡關時看一眼，真相就在裡面。*

- **Try 區塊保護**：將任何高風險、易拋出例外的操作（如非同步請求、JSON 解析、未預期運算）放入其中進行保護。
- **Catch 緩衝攔截**：當發生錯誤時立即攔截並取得 `Error` 物件，提供優雅的降級回饋與清晰日誌，避免整個網頁直接崩潰白屏。
- **Finally 保證執行**：無論 Try 成功執行還是 Catch 攔截錯誤，Finally 區塊內的程式碼均保證觸發，是關閉 Loading 動畫、釋放資源與清理狀態的最佳場所。
- **主動拋出例外**：當商業邏輯不合規（如數值異常、業務狀態碼失敗）時，搭配 `throw new Error()` 主動中斷流程並轉移至 Catch 處置。
